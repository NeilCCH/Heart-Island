# 心靈小島｜四大功能研究與規劃 v0.1
- 日期：2026-10-22
- 狀態：**研究與規劃草案，尚未授權實作**。依工作流程，需使用者裁決第 8 節待決事項並更新 PRD 後才進入實作。
- 來源：使用者提供的四大功能說明（呼吸小宇宙、3D 小貓陪伴屋、療癒小花園、今天一點點）；既有小貓能量站（第五功能）已上線於 Vercel。
- 定位延續 2026-10-22 決策：給憂鬱症患者「轉移注意力」的小程序，**非治療目的**；不加求助資源連結；免登入、不蒐集資料。

---

## 1. 共同設計原則（五個功能一致）
| 原則 | 具體做法 |
|---|---|
| 不施壓 | 沒有分數、連續打卡、排行榜、倒數壓力、未完成提醒；離開不需確認，也不會被責怪 |
| 可只看不做 | 每個功能都有「只是待著」的狀態：不操作也有安靜的畫面 |
| 低刺激 | 霧白／深藍／藍灰；動畫慢、不閃爍；聲音預設關閉、要使用者主動開 |
| 自主控制 | 速度、聲音、動畫都可調或關；尊重系統「減少動態」 |
| 隱私 | 全部在手機本機運作；不登入、不上傳、不追蹤；要保存的東西（如花園）只存本機，且可一鍵清除 |
| 無障礙 | 文字為主要資訊，不只靠顏色；按鈕 ≥ 44px；鍵盤可操作；螢幕閱讀器只播報必要短句 |
| 不宣稱療效 | 文案用「陪伴」「休息一下」「轉移注意力」，不寫「治療」「改善憂鬱」 |

## 2. 共同架構：心靈小島外殼
目前 repo 只有小貓能量站。四個新功能加入後，建議改成一個 App、一個入口：

```
心靈小島（首頁：五個入口卡片／小島地圖）
├─ 呼吸小宇宙        src/features/breath/
├─ 3D 小貓陪伴屋     src/features/companion/   ← 3D 套件只在進入時才載入
├─ 療癒小花園        src/features/garden/
├─ 今天一點點        src/features/tiny/
└─ 小貓能量站        src/features/energy/（現有）
共用：src/shared/（設計 token、按鈕、聲音引擎、設定、減少動態、主題、Wake Lock）
```
- **導覽**：不加路由套件，用簡單的畫面狀態＋網址 hash（`#breath`），讓「加入主畫面」後也能從首頁進出、上一頁返回。
- **共用設定**：聲音總開關、音量、減少動態、主題提升為 App 層設定；各功能自己的設定（呼吸速度、花園保存）放在各功能內。現有 `energy.settings.v1` 保留並遷移，不讓使用者設定遺失。
- **效能**：首頁與 2D 功能維持輕量；3D 小貓的程式與模型用動態載入（code splitting），不拖慢其他功能的開啟速度。
- **PWA**：同一個 manifest，App 名稱改為「心靈小島」；離線快取擴充到新功能的素材（3D 模型首次進入時下載並快取）。

## 3. 呼吸小宇宙
**體驗**：深色星空背景中，一顆柔和光球緩慢放大（吸）、縮小（吐）。畫面幾乎沒有文字；可以跟著呼吸，也可以只是看著。

| 項目 | 建議 |
|---|---|
| 節奏 | 沿用小貓能量站的秒數滑桿（每次 4–16 秒），預設 8 秒；可選「吐氣比吸氣長一點」（例如 4:6），預設等長 |
| 引導文字 | 預設只顯示極淡的「吸／吐」或完全隱藏（可切換）；**不計次數**，避免變成任務 |
| 聲音 | Web Audio 即時合成柔和環境音（低頻 pad＋輕微白噪），隨光球起伏微幅變化；不需要授權音檔，檔案大小為 0 |
| 減少動態 | 光球不縮放，改為亮度緩慢變化或靜態，並顯示「吸／吐」文字 |
| 技術 | CSS transform 或 Canvas 2D 即可，不需新套件；計時沿用單調時鐘、背景自動暫停的同一套原則 |
| 複雜度 | 低 |

## 4. 3D 小貓陪伴屋（重點功能）
**體驗**：小房間裡，一隻毛茸茸的橘色虎斑小貓。可以摸頭、摸臉頰；牠會眨眼、歪頭、伸懶腰、打呼嚕、睡覺。不操作時，牠會自己安靜地待著。

### 4.1 行為設計（沒有需求值、沒有懲罰）
- **閒置狀態機**：坐著 → 偶爾眨眼／歪頭／舔爪 → 久了伸懶腰 → 趴下睡覺（呼吸起伏）。純隨機、溫和節奏，不跟時間或來訪次數連動。
- **觸摸**：點擊或撫摸頭部／臉頰區域 → 瞇眼、蹭手、呼嚕聲（Android 可加輕微震動；iOS 網頁不支援震動）。
- **刻意不做**：飢餓、健康、心情值、每日登入獎勵、「好久不見」的難過表情。下次回來，小貓就是在那裡，沒有變化。
- **無障礙**：提供「摸摸頭」「摸摸臉頰」按鈕作為觸控替代；減少動態時只保留眨眼與靜態姿勢。

### 4.2 素材路線（最大的決策）
「毛茸茸」在手機網頁的即時 3D 裡是難點：真實毛髮（shell/fin、髮絲）很吃效能，通常要用烘焙貼圖模擬。三條路線：

| 路線 | 做法 | 優點 | 風險／成本 |
|---|---|---|---|
| **A. 委託 3D 美術** | 依六視角參考圖建模、綁骨、做 6–8 段動作，輸出 GLB | 品質與一致性最好，可控 | 費用與時程最高（數週）；需找合適的美術 |
| **B. AI 圖片轉 3D＋自動綁骨** | 用 Meshy、Tripo 等工具由正面圖生成 GLB，再修模、綁骨、加動作 | 快、便宜，可先做原型驗證手感 | 自動綁骨主要針對人形，四足小貓常需人工修；毛感與可愛度不穩定；需確認商用授權 |
| **C. 2.5D 動態插畫（Rive／Live2D）** | 把現有小貓拆層，做成可互動的骨骼動畫（眨眼、歪頭、呼嚕、睡覺），以狀態機回應觸摸 | 最像現在這隻貓、最可愛；檔案小、手機順；互動狀態機原生支援 | 不是真正 3D（無法轉視角）；需要會 Rive／Live2D 的動畫師或學習時間 |

**建議**：先做 **C 或 B 的一週原型**，用真實手機測「可愛度＋順暢度＋摸摸手感」，再決定是否投資 A。若「一定要 3D 可轉視角」，則 B 原型 → A 正式版。

### 4.3 技術
- 3D 路線：Three.js（建議搭配 React Three Fiber）、GLB＋Draco/Meshopt 壓縮，模型目標 ≤ 5 MB、中階手機 30–60 fps；觸摸用射線判定頭部／臉頰區域。
- 2.5D 路線：Rive 官方 React runtime（`@rive-app/react-canvas`），單一 .riv 檔通常數百 KB。
- 呼嚕聲：Web Audio 合成低頻顫動，或使用授權音效；預設關閉。
- 複雜度：**高**（素材是主要變數，程式本身中等）。這是 PRD 原本列為 Gate 5 的工作，需要另一份規格。

## 5. 療癒小花園
**體驗**：俯視的枯山水沙盤。手指劃過留下沙紋；可以種花、拖動石頭、點水面看漣漪。沒有目標，玩多久都可以。

| 項目 | 建議 |
|---|---|
| 沙紋 | Canvas 2D：沿手指軌跡畫出耙子溝槽（明暗兩線＋細顆粒），可選 1／3／5 齒耙；「抹平」按鈕一鍵重來 |
| 花與石 | 點一下種花（緩慢長出，幾種花色）；石頭可拖曳；不設數量上限，也沒有「正確擺法」 |
| 水 | 小池塘，點擊產生漣漪；減少動態時改為靜態水面 |
| 聲音 | 選用：沙沙聲、輕微水聲（合成或授權音效），預設關閉 |
| 保存 | 建議預設**保存在本機**（下次打開還是自己的花園），設定內可關閉或清除；不上傳 |
| 無障礙 | 鍵盤／按鈕替代：「隨機畫一道沙紋」「種一朵花」「移動石頭」；螢幕閱讀器簡短描述 |
| 技術 | Canvas 2D 原生即可，暫不需要 PixiJS；若之後要更細緻的光影再評估 |
| 複雜度 | 中 |

## 6. 今天一點點
**體驗**：一張卡片一件小事。可以換一張、跳過，或自己挑。做了就說「好」，沒做也沒關係。

| 項目 | 建議 |
|---|---|
| 內容 | 約 40–60 件「極小、立刻可做」的活動，分類：身體（喝一口水、伸展肩膀）、感官（看看窗外、摸摸毛毯）、環境（打開一扇窗）、聲音（聽一首歌）、溫和連結（傳個貼圖給朋友，可跳過） |
| 互動 | 「換一張」「我想自己挑」「做了」「今天先這樣」；全部不需理由 |
| 文案 | 不說「你做得很棒！」「要保持正向」；回應簡短中性，例如「好。」「收到了。」 |
| 紀錄 | 預設**不記錄**；可選「今天做過的」清單，只顯示今天，隔天自動清空，**不累計、不打卡** |
| 提醒 | 不推播、不提醒（與 PRD 一致） |
| 自訂 | 可新增自己的小事（存本機） |
| 參考 | 概念與「行為活化」中的小步驟相近，但本功能不宣稱療效；活動清單建議請心理專業人員過目一次 |
| 複雜度 | 低（主要工作是內容） |

## 7. 建議開發順序與粗估
| 階段 | 內容 | 粗估（AI 協作、及時驗收） | 需新增套件 |
|---|---|---|---|
| 1 | 心靈小島首頁外殼＋共用設定／聲音／導覽；**今天一點點**；**呼吸小宇宙** | 3–5 個工作天 | 無 |
| 2 | **療癒小花園** | 3–5 個工作天 | 無 |
| 3a | **小貓陪伴屋原型**（路線 B 或 C）、手機實測 | 約 1 週＋素材取得 | Three.js 系或 Rive（需核准） |
| 3b | 小貓正式版（依原型結論，可能含路線 A 委外） | 視素材而定（數週） | 同上 |

先做 1、2 的理由：不需外部素材、能最快讓使用者有完整的「小島」，同時平行準備小貓素材。

## 9. 風險
- 3D 毛茸茸小貓在中低階手機的效能與可愛度，是整個專案最大的不確定性，需真機原型驗證。
- AI 生成 3D 素材的商用授權與品質，需在採用前確認各工具條款。
- 內容型功能（今天一點點）的語氣對使用者影響大，建議專業人員審閱。
- 功能變多後，PWA 首次載入大小需控管；3D 只在進入陪伴屋時下載。
